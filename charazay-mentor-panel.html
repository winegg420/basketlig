A — Projede şu an ne var? (güncel özet)

localStorage · TBL G.season + tablo sıralaması Fikstür ↔ maç Keşif (3 öneri) Enerji / yorgunluk
  • Tek HTML — tüm mantık istemci tarafında; kalıcı oyun durumu hâlâ sınırlı (ağırlık localStorage lig slotları + sekmelik haber).
  • Lig tablosu: Sezon varken puan / averaj / isim sıralı; sezon yokken alfabetik yerleşim.
  • Yüksel/düş: Hâlâ “tablo sırası” heuristiğine dayanıyor; gerçek kurallar değil — bilinçli demo.
  • Ekonomi: USDT temalı; FFP, tavan, borç yok.

B — Kod / mantık tarafında dikkat (güncel riskler)

Bunlar hâlâ “revizyon yorgunluğu” ile kaçabilir; Cursor’a “B listesini doğrula” diye ver.

  • G.season kalıcılığı: Sayfa yenilenince sezon / kadro / para kaybolur — tek doğruluk kaynağı tarayıcı oturumu. Ürün hissi için save/load şart.
  • CPU maç simülasyonu: Skor rastgele aralıkta; kulüp gücü / ev sahibi ile tam bağlı değil — tablo gerçekçiliği sınırlı.
  • Beraberlik: Nadiren ayakta kalabilir; puan tablosu eşitlikte basit kural kullanıyor.
  • Antrenman: Hâlâ setTimeout demo; sekme uyku / uzun oturum edge-case’leri belirsiz.
  • Çok sekme: İki sekmede aynı dosya açılırsa state çatışması — storage event veya tek kaynak tasarımı düşünülebilir.
  • Kota / gizli pencere: İleride save büyürse QuotaExceededError ve private mode hataları yakala (aşağıdaki web özeti).

C — İnternette aranan: yeni hata / öneri özeti (web araştırması)

spor & web oyun pratikleri — Charazay mimarisine indirgeme:

  • Kayır (Basketball GM / benzeri): Büyük veri için IndexedDB tercih edilir; localStorage küçük tercihler için. Kayıtta sürüm numarası ve migrasyon olmadan eski save’ler kırılır.
  • Veri kaybı senaryoları: Tarayıcı “çıkışta sil”, manuel cache temizliği, düşük disk (özellikle mobil) — kullanıcıya dışa aktar / içe aktar ikilisi şart.
  • Çok sekme: Aynı origin’de storage event ile sekmeler arası senkron mümkün; kaynak sekme kendi yazısında event almaz — tasarımda dikkat.
  • Hata ayıklama: Konsol log + export/import ile izolasyon (Basketball GM dokümantasyonu benzeri yaklaşım).

Okuma: Basketball GM — Debugging · FAQ (export/import) · Game save — web best practices · web.dev — IndexedDB · MDN — storage quotas
